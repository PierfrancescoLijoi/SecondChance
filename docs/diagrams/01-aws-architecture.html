Architecture · as deployed by infra/terraform · eu-central-1

SecondChance on AWS: serverless, tenant-isolated, private by default

ADR-003 · ADR-011 · ADR-017

Isolation lives in the database

  • The token proves who the caller is; the membership table, read on every request, decides the role and tenant.
  • Every transaction, from the API, a worker or a tool call, runs SET LOCAL for tenant, role and subject; RLS covers offers, chunks, runs, steps and memory.
  • Each Lambda family connects through RDS Proxy as its own database user with an IAM token; none has BYPASSRLS. S3 access is limited to tenants/*.

ADR-005 · ADR-006 · ADR-010

Stateless compute, durable state

  • Step Functions Standard drives one bounded agent-step invocation at a time; runs, leases and budgets live in Aurora.
  • Three queues (jobs, notify, realtime-events), each with a DLQ; messages carry identifiers only. requeue recovers lost work every few minutes.
  • No NAT: VPC Lambdas use endpoints for SQS, Bedrock, Secrets Manager, Lambda, Step Functions, S3 and DynamoDB. The notifier, the WebSocket authorizer and the publisher run outside the VPC with no data permission.

ADR-012 · ADR-015 · NFR-013

Governed tools, traced end to end

  • Agent tools cross the MCP Gateway (allow-list, schema, DynamoDB quota, audit) before the private tool executor, which acts only for the active run step.
  • CloudWatch logs and alarms to SNS, X-Ray tracing, an account-wide budget; one correlation ID across API, queues, agent steps and audit.
  • Locally: Bedrock ↔ Ollama · SQS ↔ ElasticMQ · S3 ↔ SeaweedFS · SES ↔ Mailpit · ADOT ↔ otel-lgtm.
