Architecture · SecondChance v0.3 · eu-central-1

SecondChance on AWS: serverless, tenant-isolated, idle at zero

ADR-003 · ADR-011

Isolation lives in the database

  • Every transaction, from an API request or an agent step, runs SET LOCAL app.tenant_id from the verified token.
  • RLS covers offers, chunks, agent runs, steps and memory; no tool takes tenant_id as an argument.
  • S3 keys come from the same context: tenants/{tenant_id}/{area}/{id}, ABAC session tag on AWS.

ADR-001 · ADR-006 · ADR-010

Stateless compute, near-zero cost at rest

  • Three queues, each with a DLQ; messages carry IDs only. The agents worker runs one bounded step per message and enqueues the next after commit.
  • Aurora pauses at 0 ACU; no NAT Gateway. xray and logs endpoints only if ADOT export from the VPC needs them (check in P4).
  • Notify needs no database, so it runs outside the VPC and calls SES directly.

ADR-012 · NFR-013

Traced end to end, same code locally

  • One correlation ID across API, SQS attributes, agent steps and audit; no prompts in logs.
  • Bedrock ↔ Ollama · SQS ↔ ElasticMQ · S3 ↔ SeaweedFS · ADOT ↔ otel-lgtm.
